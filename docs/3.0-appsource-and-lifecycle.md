# 3.0. PTE, Marketplace и жизненный цикл расширения

[Оглавление](README.md)

## Способ доставки

PTE предназначено для конкретного tenant. Marketplace app распространяется через каталог и проходит предусмотренную Microsoft проверку. Учебная публикация из VS Code — рабочий цикл разработчика, а не полный процесс поставки production-приложения.

| Вопрос | PTE | Marketplace |
|---|---|---|
| Аудитория | Конкретный заказчик | Несколько клиентов |
| Доставка | Управляемая установка для tenant | Публикация и обновления каталога |
| Совместимость | Обязательна для обновления заказчика | Обязательна для поддерживаемой аудитории |
| Диапазон | Обычно диапазон кастомизации | Выделенный диапазон издателя |

Объекты 50000–99999 подходят для обучения и кастомизации. Для Marketplace запрашивают подходящий диапазон и регистрируют affix. Affix снижает конфликты имён, но не заменяет уникальность ID и App ID. [Object ranges](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-object-ranges).

## Что должно быть готово к поставке

Нужны воспроизводимый пакет, корректные dependencies, permissions, переводимые строки, тесты установки и обновления, документация пользователя и поддерживаемые версии. Для Marketplace дополнительно проверяют действующие требования к предложению и технической валидации. Их нужно перечитывать перед реальной отправкой. [Technical validation](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-checklist-submission).

CodeCop проверяет общие правила AL, UICop — требования UI, AppSourceCop — правила Marketplace и совместимость с baseline, PerTenantExtensionCop — соответствующие ограничения PTE. Анализаторы не доказывают правильность финансового результата.

## Данные переживают исходники

После первой установки таблица уже содержит данные клиента. Удаление поля, смена его типа, сокращение длины или изменение ключа могут нарушить совместимость. Изменение Caption обычно относится к UI; повторное использование старого field ID под другой смысл — к идентичности данных.

Пример эволюции:

1. В v1 есть Note Text длиной 100.
2. В v2 нужна новая структура хранения.
3. Добавьте совместимые новые поля или таблицу.
4. Напишите перенос существующих значений.
5. Сделайте повторное выполнение upgrade безопасным.
6. Переведите чтение/запись на новую модель.
7. Пометьте старый API/поле obsolete с объяснением и версией.
8. Удаляйте только по допустимой политике совместимости и поддержки.

ObsoleteState = Pending предупреждает об устаревании; дальнейший переход имеет ограничения по типу объекта. Это не команда немедленно стереть все клиентские данные.

## Install и Upgrade

Install Codeunit обслуживает установку, Upgrade Codeunit — переход версии и данных. Различайте обработку каждой Company и общих данных. Успешная установка на пустой базе не проверяет перенос тысяч исторических записей.

Для upgrade нужны минимальная поддерживаемая исходная версия, контроль уже выполненных шагов, обработка частичных состояний и наблюдаемый результат. Не используйте ForceSync как production-миграцию по умолчанию.

## Pipeline

```text
Checkout → symbols → compile/analyzers → tests
→ install test → upgrade from baseline → package → controlled deployment
```

Baseline — реальная опубликованная версия, с которой обновляются пользователи. Храните её пакет и тестовые сценарии. Проверяйте не только latest BC, но и заявленный минимальный вариант.

Пакет тестов обычно отделяют от бизнес-приложения. Library Assert и Application Test Library не должны случайно стать обязательным требованием обычной установки, если они нужны только тестам.

## Обслуживание

Обновления BC могут менять deprecated API, runtime и поведение. Проверяйте предстоящие версии в sandbox, изучайте предупреждения и не откладывайте миграцию до блокировки обновления клиента. [Maintain apps and PTEs](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/app-maintain).

**Практика:** опишите изменение Item Note v1 → v2, подготовьте данные старой версии и докажите их сохранность после upgrade. Зафиксируйте, какие permissions, UI и tests изменились.

**Почему переустановка не равна upgrade?** Она может не проверить путь преобразования существующих данных и зависимостей.
