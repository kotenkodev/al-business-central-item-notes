# 4.2. Диагностика проблем BC и AL

[Оглавление](README.md)

## Сначала воспроизводимый факт

Сохраните Company, пользователя, версию, документ, действие, дату и полный текст ошибки. При ошибке AL добавьте call stack и первую диагностическую ошибку сборки. Не исправляйте сразу несколько настроек: иначе причина останется неизвестной.

| Симптом | Первая проверка | Затем |
|---|---|---|
| Не хватает товара | Location, Variant, базовая единица | Reservations, tracking, bins |
| Нельзя Ship из заказа | Require Shipment | Открытый Warehouse Shipment |
| Pick пустой | Pickable bins и размещение | Блокировки, партия, чужие задания |
| Tracking quantity mismatch | Qty. to Handle (Base) | Частично проведённые назначения |
| Нет Posting Setup | Точная комбинация групп из ошибки | Правильность исходных справочников |
| Стоимость продажи изменилась | Поздний invoice/charge | Cost adjustment и цепочка применения |
| Нет General Ledger cost | Automatic Cost Posting | Post Inventory Cost to G/L и ошибки |
| Нет прав | Object type, ID, действие | Effective Permissions и entitlement |
| Symbol not found | Dependency и версия | Загрузка symbols выбранной среды |
| Схема не синхронизируется | Несовместимое изменение поля | Поддерживаемый upgrade |
| Breakpoint не срабатывает | Установленная версия и session | Реальный путь вызова |

## Format on save: конкретно этот проект

Проверены `.vscode/settings.json` и пользовательские настройки VS Code. В проекте есть editor.formatOnSave=true и override `[al]` с editor.defaultFormatter=ms-dynamics-smb.al. Расширение Microsoft AL установлено. Поэтому отсутствие этих настроек не подтверждается.

Глобальный Prettier не должен перекрывать корректный language-specific override в открытом workspace. Однако активный профиль, remote context и другой открытый корень редактора могут изменить эффективные настройки. [VS Code settings](https://code.visualstudio.com/docs/configure/settings).

### Как различить неисправность и ожидаемый результат

1. Откройте SyntaxPractice.Codeunit.al и проверьте язык AL в строке состояния.
2. Внутри begin/end временно нарушьте отступ одной строки.
3. Выполните Format Document With… и выберите Microsoft AL.
4. Если отступ исправился, formatter работает. Отмените пробное изменение.
5. Повторите с Ctrl+S: это отдельно проверяет save hook.
6. Если ручная команда работает, а сохранение нет, проверьте эффективные настройки для AL, formatOnSaveMode и активный workspace/profile.
7. Если не работает и ручная команда, проверьте Problems, Output → AL и состояние расширения; при зависшем language server используйте Developer: Reload Window.

AL formatter работает по синтаксическому дереву и собственным правилам. Он не является Prettier для AL и не обещает удалять каждую лишнюю пустую строку. Неизменившиеся пустые строки в конце Codeunit сами по себе не доказывают отказ. [AL formatter](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-al-formatter).

Причина отказа сохранения в активном окне не установлена: для её подтверждения нужен результат ручного Format Document или журнал этого окна. Настройки не изменены, поскольку нужные значения уже заданы.

### Отдельная логическая проблема SyntaxPractice

GetShippingFee объявляет результат Decimal, вычисляет ShippingFee и показывает Message, но не выполняет exit(ShippingFee). GetCurrencyRate аналогично показывает значение, но явно его не возвращает. Для вызывающего кода сообщение и результат функции — разные вещи.

Если процедура задумана как расчёт, возвращайте значение и показывайте его на уровне вызывающего UI. Если задумана только как демонстрация сообщений, уберите ненужный return type при соответствующем изменении контракта. Это не исправляется форматированием. Код здесь не изменялся: текущая задача — документация.

## Ошибка после частичного успеха

Перед повтором выясните, был ли Commit или внешний эффект. Если invoice уже проведён, повтор создания нового документа может дать дубль. Если HTTP-запрос ушёл, локальный rollback не означает, что удалённая операция отменена.
