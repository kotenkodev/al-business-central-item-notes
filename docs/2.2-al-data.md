# 2.2. Record, фильтры, изменения и FlowFields

[Оглавление](README.md) · [Логика](2.3-al-logic-and-transactions.md)

## Record — буфер плюс состояние запроса

Переменная Record содержит значения текущей строки, фильтры, текущий ключ и другие настройки чтения. Присвоить поле в буфере не означает сохранить его в базе. SetRange не загружает запись; CalcFields не проводит документ.

## Выбор метода

| Метод | Назначение | Ловушка |
|---|---|---|
| Get | Найти по первичному ключу | Обычные фильтры не ограничивают поиск |
| FindFirst / FindLast | Первая/последняя запись текущей выборки | Порядок зависит от ключа |
| FindSet | Обойти набор | Нужен Next и обработка пустого результата |
| IsEmpty | Проверить существование строк | Не загружает полезную текущую запись |
| Count | Посчитать выборку | Не нужен, если требуется только существование |
| SetRange | Точное значение или интервал | Заменяет фильтр данного поля в текущей группе |
| SetFilter | Выражение фильтра | Метасимволы имеют смысл |

Get использует первичный ключ и игнорирует обычные фильтры, но security filters имеют отдельные правила. Не используйте его как доказательство принадлежности записи выбранному бизнес-набору. Пропущенные последние части составного ключа получают значения по умолчанию. [Get](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/methods-auto/record/record-get-method).

```al
local procedure CountNotes(ItemNo: Code[20]): Integer
var
    Note: Record "Item Note";
begin
    Note.SetRange("Item No.", ItemNo);
    exit(Note.Count());
end;
```

## Фильтры и ключи

SetRange(Field) очищает фильтр одного поля. SetFilter поддерживает диапазоны, альтернативы, сравнения и шаблоны. Для точного пользовательского значения безопаснее по смыслу SetRange, чем самостоятельная сборка filter string.

FilterGroup меняет группу, в которой задаются фильтры; системные группы могут сохранять ограничения независимо от видимых пользовательских фильтров. После временной смены восстанавливайте предыдущую группу.

SetCurrentKey предлагает сортировку по подходящему ключу, но не создаёт индекс и не гарантирует желаемый план SQL. Учитывайте первичный ключ как дополнительный порядок при одинаковых значениях.

Reset сбрасывает фильтры, ключ, marks, настройки загрузки и другие состояния; это не эквивалент очистки значений полей. Init и Clear имеют другое назначение. [Reset](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/methods-auto/record/record-reset-method).

## Вставка и изменение

```al
local procedure AddNote(ItemNo: Code[20]; NoteText: Text[100])
var
    Note: Record "Item Note";
begin
    Note.Init();
    Note."Entry No." := 0;
    Note.Validate("Item No.", ItemNo);
    Note.Validate("Note Text", NoteText);
    Note.Insert(true);
end;
```

Init не является универсальным сбросом всех ключевых значений повторно используемого буфера. Для AutoIncrement здесь явно задаётся ноль. Validate выполняет проверку поля и его OnValidate; присваивание := её не вызывает. Insert(true) включает OnInsert, но не выполняет автоматически Validate каждого поля. Аналогично Modify(true) включает OnModify, а не все OnValidate. [Record methods](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/methods-auto/record/record-data-type).

Для удаления тоже важно RunTrigger и зависимости. DeleteAll по неверно отфильтрованному Record может удалить больше строк, чем ожидалось. ModifyAll не заменяет последовательные Validate с их бизнес-эффектами.

## Обход с обновлением

```al
local procedure RaisePriority(ItemNo: Code[20])
var
    Note: Record "Item Note";
begin
    Note.SetRange("Item No.", ItemNo);
    if Note.FindSet(true) then
        repeat
            Note.Validate(Priority, Enum::"Item Priority"::High);
            Note.Modify(true);
        until Note.Next() = 0;
end;
```

FindSet(true) выражает намерение обновлять набор и влияет на блокировки. Оно не решает все возможные гонки. Изменение поля, входящего в фильтр или ключ обхода, требует отдельного анализа; для сложной обработки сначала фиксируют идентификаторы или используют другой алгоритм.

## FlowField и FlowFilter

FlowField хранит формулу вычисления, а не итоговую сумму в обычной физической колонке. Например, Note Count может считать связанные Item Note. FlowFilter параметризует расчёт и сам не является обычным хранимым значением записи.

```al
Item.Get(ItemNo);
Item.CalcFields("Note Count");
Message('%1', Item."Note Count");
```

В AL перед чтением обычно нужен CalcFields либо SetAutoCalcFields. Страница умеет вычислять связанные FlowFields автоматически в соответствующем контексте. Поведение скрытых controls зависит от версии и функции Calculate only visible FlowFields. Не рассчитывайте на UI-вычисление в фоновом Codeunit. [FlowFields](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-flowfields).

CalcSums агрегирует подходящие обычные поля; это не тот же вызов, что CalcFields. SIFT помогает определённым агрегатам, но наличие FlowField не гарантирует бесплатный запрос.

## Temporary records

Record temporary использует структуру таблицы как буфер в памяти. Insert создаёт временную строку, а не постоянную бизнес-запись. Это удобно для Name/Value Buffer в SyntaxPractice.

Однако вызванный из temporary-триггера код может обратиться к постоянной таблице. Temporary не является песочницей для всех побочных эффектов. Перед повторным заполнением списка решите, нужно ли очищать предыдущие строки: повторный Insert того же ключа может дать duplicate key.

## Производительность

Не загружайте все записи ради одного Exists. Для больших наборов выбирайте подходящие фильтры и поля. SetLoadFields сокращает первоначальную загрузку, но обращение к незагруженному полю может вызвать дополнительное чтение. FlowField в каждом проходе большого цикла способен создать множество SQL-запросов.

Измеряйте количество запросов, время и блокировки. Ускорение без сохранения бизнес-правил не считается улучшением. Прямая вставка в Item Ledger Entry вместо стандартного posting недопустима как «оптимизация».

## Практика и ответы

Создайте две заметки для одного товара и одну для другого. Проверьте Count с фильтром, Get по Entry No., обход только первого товара и FlowField после вставки.

**Почему Get вернул строку другого Item No.?** Он искал по первичному ключу, а обычный фильтр не ограничивает этот поиск.

**Почему после присваивания поле не сохранилось?** Был изменён только буфер, без Modify/Insert.

**Почему CalcFields показывает другое число?** Проверьте FlowFilters, формулу и фактические связанные строки.
