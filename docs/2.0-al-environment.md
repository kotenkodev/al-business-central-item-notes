# 2.0. Среда разработки AL

[Оглавление](README.md) · [Далее: объекты](2.1-al-objects.md)

## От исходника к приложению

AL компилируется в пакет `.app`. Сервер публикует пакет, синхронизирует схему и устанавливает приложение либо обновляет существующую версию. Это разные операции: наличие пакета на сервере ещё не доказывает, что приложение установлено в нужном tenant.

VS Code редактирует код и запускает инструменты расширения AL Language. Сам редактор не исполняет серверную бизнес-логику. Symbols описывают доступные объекты зависимостей; они нужны компилятору и IntelliSense, но не являются копией данных компании.

## Файлы проекта

| Файл / каталог | Назначение |
|---|---|
| app.json | Идентичность приложения, версии, зависимости, диапазоны объектов |
| .vscode/launch.json | Подключение, публикация, запуск отладки |
| .vscode/settings.json | Настройки редактора и анализаторов |
| .alpackages | Загруженные symbol packages |
| src | Исходные объекты |
| .app | Результат сборки |

В этом репозитории проект уже существует. Повторять AL: Go! поверх него не нужно. Для нового независимого упражнения команду запускают в отдельной пустой папке. [Get started with AL](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-get-started).

## Четыре разных версии

| Поле | Что означает |
|---|---|
| version | Версия вашего приложения |
| platform | Минимальное требование к платформенным символам |
| application | Минимальная версия Application dependency |
| runtime | Набор возможностей AL и требования к исполняющей среде |

Номер AL Language extension — ещё одна версия. Его нельзя механически копировать в runtime. BC 29.0 соответствует runtime 18.0; приложение 29.1 не подразумевает runtime 18.1.

Текущий app.json проекта содержит runtime 18.0, application 29.1.57326.58076 и platform 1.0.0.0. Последнее является объявленным минимальным требованием, а не утверждением, что сервер работает на платформе 1.0. Не меняйте версии наугад ради исчезновения ошибки загрузки symbols. [Manifest](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-json-files), [runtime](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-choosing-runtime).

## Идентичность и зависимости

App ID — постоянная идентичность приложения. Смена GUID вместо увеличения version создаёт другое приложение и не выполняет обычное обновление старых данных. Имя файла пакета не заменяет идентичность из manifest.

Каждая dependency должна соответствовать реально используемой возможности и быть доступна при сборке и установке. Не добавляйте все приложения среды автоматически: это расширяет требования к установке. В текущем проекте есть тестовые библиотеки; для поставки обычно выделяют отдельное тестовое приложение.

Диапазон проекта сейчас 50100–50149. Новые примеры должны учитывать занятые ID. Диапазон 50000–99999 подходит для обучения/PTE, но не является универсальным диапазоном Marketplace.

## Локальное подключение

Пример конфигурации, **если** имя сервиса BC, tenant default и порт разработки 7049 соответствуют вашему контейнеру:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Local training",
      "type": "al",
      "request": "launch",
      "environmentType": "OnPrem",
      "server": "http://test",
      "serverInstance": "BC",
      "port": 7049,
      "authentication": "UserPassword",
      "tenant": "default",
      "schemaUpdateMode": "Synchronize",
      "breakOnError": "All"
    }
  ]
}
```

Это шаблон, а не проверенный адрес сервера. URL веб-клиента и endpoint сервиса разработки различаются. Рабочая страница в браузере не доказывает доступность порта разработки. Пароль вводится через механизм аутентификации, а не записывается в JSON. [Launch configuration](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-json-launch-file).

## Порядок проверки

1. Откройте корень проекта с app.json.
2. Проверьте, что AL Language активировано и файл распознан как AL.
3. Выполните AL: Download Symbols для выбранной среды.
4. Проверьте Output и Problems: первая ошибка часто объясняет следующие.
5. Выполните AL: Package. Сборка не требует проведения бизнес-документов.
6. Публикуйте в учебную среду и проверьте Extension Management.
7. Откройте нужную страницу в правильной Company.

Synchronize сохраняет совместимость схемы в рамках поддерживаемых изменений. Recreate и ForceSync не являются обычным способом исправлять миграции: они могут привести к потере данных. Обновление схемы рассматривается в [3.0](3.0-appsource-and-lifecycle.md).

## Отладка

Breakpoint должен попасть в исполняемую процедуру нужной версии приложения. Если он не срабатывает, проверьте session, Company, опубликованный пакет, resourceExposurePolicy и путь вызова. Открытая страница может выполнять другой объект, чем предполагает имя файла.

На остановке изучайте call stack, Rec, xRec, фильтры и значения параметров. Step Into раскрывает вызов, Step Over выполняет его целиком. Переход к Error позволяет увидеть причину до завершения транзакции. [Debugging](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-debugging).

## Форматирование и редактор

Для AL нужен Microsoft formatter. Настройки проекта уже содержат правильный language-specific override. Глобальный Prettier не должен его заменять, если открыт именно этот workspace.

```json
{
  "[al]": {
    "editor.defaultFormatter": "ms-dynamics-smb.al",
    "editor.formatOnSave": true
  }
}
```

Форматирование меняет оформление; оно не вставит недостающий exit с результатом функции. Проверка конкретного SyntaxPractice находится в [диагностике](4.2-troubleshooting.md).

## Практика и самопроверка

Соберите проект, откройте определение Record Item из symbols, найдите собственную таблицу через Page Inspection. Зафиксируйте отдельно версию manifest и установленного приложения.

**Почему symbols скачались, а публикация не удалась?** Сборка, серверные права, зависимости и синхронизация схемы проверяются на разных этапах.

**Можно ли считать успешную сборку успешным тестом?** Нет: она проверяет статическую корректность, а не бизнес-результат.
