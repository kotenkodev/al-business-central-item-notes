# 2.1. Объекты, синтаксис и модель приложения

[Оглавление](README.md) · [Данные](2.2-al-data.md)

## Объект — единица метаданных

| Объект | Ответственность |
|---|---|
| Table | Данные, ключи, ограничения и триггеры |
| Page | Представление и взаимодействие |
| Codeunit | Процедуры и бизнес-операции |
| Enum | Именованный набор значений |
| TableExtension | Дополнительные поля и логика таблицы |
| PageExtension | Дополнение интерфейса |
| PermissionSet | Декларация прав |
| Report / Query | Отчётность и чтение наборов данных |

ID относится к объекту определённого типа; Table 50100 и Codeunit 50100 могут существовать одновременно. Внутри таблицы field ID имеет свою идентичность. Переименовать отображаемую Caption и заменить номер поля — совсем разные изменения для обновления данных. [Objects](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-dev-overview).

## Синтаксис, который нужно читать уверенно

Одинарные кавычки задают строковый литерал: 'Hello'. Двойные кавычки позволяют использовать идентификатор с пробелом: "Item No.". Присваивание — :=, сравнение — =. Блок begin/end объединяет операторы. Перед else не ставят завершающую точку с запятой предыдущей ветки.

```al
local procedure ShippingFee(OrderTotal: Decimal; IsVIP: Boolean): Decimal
begin
    if IsVIP or (OrderTotal >= 100) then
        exit(0);
    if OrderTotal >= 50 then
        exit(5);
    exit(10);
end;
```

Это самостоятельный фрагмент для включения внутрь Codeunit. Возвращаемое значение и Message — разные действия. Message показывает текст, но не устанавливает результат процедуры.

## Типы и значения

| Тип | Тонкость |
|---|---|
| Code[n] | Нормализация регистра и пробелов; подходит для кодов |
| Text[n] | Текст с ограничением длины |
| Decimal | Количества и деньги; округление задают по смыслу |
| Integer / BigInteger | Целые с разными диапазонами |
| Boolean | true / false |
| Date / DateTime | Дата и момент времени — разные сущности |
| Guid | Устойчивый идентификатор |
| Enum | Значение предметной области |
| List / Dictionary | Коллекции в памяти |
| Record | Буфер записи и состояние выборки таблицы |

Пустая дата 0D не равна сегодняшней. WorkDate и Today также могут различаться. Формат отображения даты не должен становиться форматом машинного интеграционного контракта.

## Параметры и область видимости

local procedure доступна внутри объекта; обычная procedure может служить API объекта в рамках правил доступа. var позволяет изменять переданную переменную вызывающего кода. Без var Record-буфер передаётся как значение, но запись в постоянную таблицу через этот буфер всё равно меняет базу.

List и Dictionary имеют семантику ссылочных типов: не переносите правило копирования Record на все типы. Глобальные переменные живут в контексте экземпляра объекта; SingleInstance имеет особое время жизни и не годится для неявного хранения состояния каждого пользователя «навсегда».

## Учебная модель этого проекта

В проекте уже есть Item Note, Item Priority, Item Note Helper, страницы и extensions. Используйте их как связанную модель:

```text
Item → много Item Note
Item Note.Priority → Item Priority
Item Notes Page → отображает Item Note
Item Note Helper → создаёт и изменяет заметки
Item Card extension → вход в функцию из карточки товара
```

TableRelation = Item."No." задаёт связь и стандартную проверку/lookup при соответствующих операциях. Это не универсальный SQL foreign key и не автоматическое каскадное удаление всех заметок при удалении Item.

AutoIncrement генерирует идентификатор, но не обещает непрерывную последовательность без пропусков. Для бизнес-номеров документов используют No. Series, а не эстетическое переименование Entry No.

## Где размещать правило

Проверка «заметка не должна быть пустой» нужна на серверном пути записи. Если оставить её только на Page, другой Codeunit или API может обойти страницу.

В текущей таблице OnValidate проверяет Note Text, а OnInsert дополнительно защищает вставку с включённым триггером. Однако прямое присваивание, Modify(false) или Insert(false) могут обходить части прикладной логики. Внутренние процедуры приложения должны соблюдать выбранный контракт записи.

Проверка перехода состояния обычно относится к service Codeunit, который управляет операцией. Page вызывает сервис, а не дублирует его алгоритм в каждой кнопке.

## Extensions

TableExtension добавляет хранимое поле, PageExtension делает его доступным в UI. Добавление только page control не создаёт постоянную колонку. SourceExpr может быть переменной, вычислением или полем — их жизненный цикл различается.

Для стандартных объектов не копируйте большой posting Codeunit ради маленькой проверки: ищите поддерживаемую точку расширения. Члены с Internal access требуют учитывать границы приложения.

Enum с Extensible = true допускает новые значения других расширений. Код case должен осмысленно обрабатывать неподдерживаемые значения, а не предполагать, что список навсегда закрыт. [Enums](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-extensible-enums).

## UI и перевод

Caption — отображаемый текст, Name — техническое имя. Для пользовательских сообщений используют Label и переводимые ресурсы. ToolTip должен объяснять смысл поля. ApplicationArea, UsageCategory и разрешения влияют на доступность страницы разными способами.

Права на собственную таблицу нужны отдельно от наличия страницы. Не подтверждайте готовность приложения проверкой только под SUPER.

## Практика

1. Проследите Item No. от Page к TableRelation и процедуре создания заметки.
2. Создайте заметку через UI, затем через Codeunit.
3. Проверьте пустой Note Text на обоих путях.
4. Добавьте отображение существующего поля на страницу, не создавая дублирующее поле таблицы.
5. Найдите ID и source extension через Page Inspection.

**Почему Message не возвращает Decimal?** UI-эффект не присваивает результат функции.

**Почему поле на странице не всегда сохранено?** Оно может быть связано с переменной вместо постоянного поля таблицы.
